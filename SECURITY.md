# Security

## Reporting a vulnerability

Use GitHub private vulnerability reporting when it is enabled for the repository. Otherwise, contact **supportbaystudio@gmail.com** with a minimal description and a safe reproduction procedure. Do not disclose exploitable details in a public issue before maintainers have had an opportunity to investigate.

Include the affected version, Android version, impact, prerequisites, and reproduction steps. Do not send live credentials or private signing keys.

## Security-sensitive areas

File publication and recovery, process ownership, external tool execution, browser automation, authentication, provider credentials, and dependency verification require particular care. Changes must retain authorization boundaries, cancellation handling, and ownership checks.

## Supported fixes

Security fixes are applied to the maintained release line. A response time or maintenance period is not guaranteed by this document. Older releases may require an application update to receive a fix.
