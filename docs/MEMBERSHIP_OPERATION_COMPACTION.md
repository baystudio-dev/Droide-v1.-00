# Explicit operation-backed membership envelope compaction

This opt-in service API uses a forward-only schema3-to4 migration under the selected-store and journal writer authority. Older software rejects schema4; existing factories and UI callers do not migrate or invoke it automatically. Call enableMembershipCommands first, then explicitly enableMembershipCompaction on the selected store. Pending preparation refuses migration. Existing legacy operation classifications and full command receipts remain intact.

After explicit membership-service acceptance, expireAcceptedOperation(token, exactOutcome) may replace that full command envelope with a typed compact link. It preserves the original operation-to-token mapping, exact retained completion and all custody. The link binds enrolled authority, fixed recipient, token, operation UUID, completion and reconstructed PREPARED hashes. Request and accepted-envelope hashes are commitments captured from the validated transition, not reconstruction of dropped proposal bytes. Whole membership counts/digest and bidirectional mapping are validated on every read. No-change expiry remains a separate operation.

Old command discovery/ack/repeated expiry is unavailable, not a claim of prior success or permission to replay. Normal canonical receipt reads/resume still use the original retained operation, never the compact envelope. UUID uniqueness remains probabilistic; no sequence floor or eternal nonreuse claim. New UUIDs are checked against full and compact tokens. Compaction neither adopts historical project state nor clears uncertainty; no current project-root liveness is claimed.

The4096-byte maximum compact record is charged to the logical8MiB envelope budget. Full tracked records reserve the larger of their completed envelope and possible compact shape; migration reserves this too. Full command slots and large proposal-envelope bytes can be recovered. Compact links stay bounded by canonical128; mappings by129 including a pending operation. Canonical entry/retained-byte/metadata charges never decrease, all three custody files remain, and publication still refuses at canonical128. SQLite pages/index bytes are not represented by envelope charge, and no disk reclamation is claimed. No physical release, automatic ack/expiry, default activation, UI/native changes or arbitrary-process closure.

Tests use actual synthetic journal/store/manager fixtures: migration, normal compaction, history and legacy mapping preservation, canonical PREPARED byte reconstruction, unavailable old tokens, malformed and recomputed-but-wrong linkage, pending ordinary work, cancellation/rollback/lost return, logical slot recovery and actual128 canonical receipts/384 custody files unchanged. Injected transaction checkpoints do not certify power-loss durability or device execution.
