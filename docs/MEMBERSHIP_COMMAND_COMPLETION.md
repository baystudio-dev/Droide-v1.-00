# Exact staged membership command completion

The explicit manager/store API completeMembershipCommand(token, operationId, admissionEnvelopeHash) publishes only an already tracked PUBLICATION_STAGED command through the existing canonical resume implementation. It never admits a new command, prepares missing work, adopts projects/active/recents, acknowledges delivery or clears manager uncertainty. Existing callers/default routes are unchanged; no schema migration is added.

admissionEnvelopeHash is SHA256 of the canonical operation-backed full receipt normalized only to outcome=null and acknowledged=false. All request/authority/token/operation/frozen-intent fields remain bound. This matches the original unresolved envelope and survives completion and explicit acceptance. No-change receipts are ineligible. Missing/compacted commands are unavailable, never recreated.

The staged mutation branch validates exact original catalog Version, all-five custody inventory, target root, enrolled application/selection, command and history. It uses one updater serialization and the existing resume body via a private helper, with a local root/app guard around its journal and direct callbacks, including final custody review. No recursive lock or alternative publication algorithm is added. Existing public resume behavior remains delegated to the same body. Preparation phases and intermediate retirement/publication ambiguity phases refuse through this new service; they require separate explicit review. This is not a claim all recovery phases are now exposed.

An already-completed full command takes a strictly read-only historical-result branch. It verifies original history/receipt set and exact archived custody after callbacks; it does not require old proposal to remain current, target root to remain live, or manager state to match. The actual acknowledgement bit is returned. A later ordinary publication or another pending operation is not resumed/replaced/adopted. Historical result is not current workspace readiness or human/UI delivery.

Failures never trigger an automatic second resume. Existing cancellation/fatal/unconfirmed categories remain. If archive committed before a lost return, a later explicit call can retrieve that exact historical receipt. If outcome remains in unsupported native phases, evidence stays preserved and the service refuses. No physical cleanup or canonical retention credit is granted. Successful mutation result is followed by exact custody/history/receipt revalidation after the last callback before return.

Tests use fresh synthetic real journal/store/manager fixtures: stage-to-completion handoff, stable identity, early/late phase refusal, same-byte original/custody replacement, actual cancellation/fatal and lost returns, schema4, historical root absence/later writer/other pending work, changed acknowledgement during review and no adoption/ack/reset. No native rebuild/device/power-loss/global arbitrary-writer certification.
