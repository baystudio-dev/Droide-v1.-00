# Explicit interrupted membership command recovery

The selected journaled store and manager expose recoverMembershipCommand(token, operationId, admissionEnvelopeHash). This is an explicit service operation, not a default startup or UI action. It shares exact admitted-command binding and final historical-result proof with completion, without broadening completion's STAGED-only mutation contract.

Unresolved recovery accepts retirement prepared/recorded/recovered, retained snapshot, publication prepared/recorded/recovered/completed phases only. The existing raw resume implementation owns each phase's evidence requirements. A retirement intent committed before the move refuses: the original still exists and no exact retired inode proves the move. A publication intent committed before the move likewise refuses. After an observed move with a missing return/receipt, existing recovery validates exact versions, forces retained files/directories and records recovery without issuing that move again. Successful retirement recovery can perform the first publication of the already admitted proposal.

Early preparation and STAGED use their separate explicit services. Unknown, compacted, no-change, foreign or mismatched identities do not admit anything. A completed full receipt returns historical outcome and actual acknowledgement bit, not current catalog state; later ordinary writes and absent historical target roots do not make old state current. Manager projects/active/recents and uncertainty are not changed by this service.

Cancellation or failure can occur after durable phase advancement. No automatic second attempt is made, and no universal rollback is claimed. A later explicit request inspects the persisted phase. Inconsistent custody, recreated paths, inode substitutions or unsupported receipts remain preserved and blocked. This does not establish global writer exclusion, cleanup permission, canonical capacity credit or crash/power-loss certification.
