# Catalog release preflight (observation only)

`CatalogReleasePreflight` is a pure in-memory evaluator of two supplied snapshots and current editor/process observations. The evaluator itself has no mutation or UI route. The subsequent opt-in ProjectCatalogUpdate collector is documented in CATALOG_PREFLIGHT_COLLECTOR.md. Its DTOs are synthetic inputs, not certified evidence. Any collector must obtain the raw completed-operation records and existing policy from the same validated authority inspection, decode and cross-check record fields, and establish the exact authority/root/catalog/custody provenance. Callers must not mix fields from different observations or infer that empty subsystem lists establish writer exclusion.

The only successful result is `ObservedForReview`, carrying the explicit limitation: physical release is unavailable until writer admission and durable retirement are integrated. `Blocked` keeps separate causes. Unavailable snapshot, editor or process evidence fails closed. There is no release method or authorization token.

The evaluator canonicalizes all bounded history entries into the schema-2 length-prefixed SHA-256 encoding of durable policy, operation ID, retained byte charge and exact encoded record. Selected record digests and exact retained `.before`, `.after` and `.retired` versions are copied into the observation in deterministic order. It rejects duplicate selections/records/custody names, unknown selections, wrong owners, non-REPLACE/non-projects.json records, malformed versions, missing custody roles, negative/overflow accounting and exhausted capacity. Policy changes, changed raw history, root/authority/owner/generation changes and selected custody changes block review.

The original pure-evaluator increment modified no existing production files; the subsequent read-only collector increment changes the journal and catalog classes. This implementation does not persist review state, delete files, remove receipts, credit capacity, acknowledge editor state, save buffers, stop processes, activate the journaled store, change retention limits or migrate schemas. Full-history retry behavior remains unchanged. The opt-in collector supplies journal/catalog provenance; a production held-admission protocol and complete process/descriptor coverage is still missing; participating-ledger diagnostics are documented in CATALOG_PROCESS_OBSERVATION.md; the later opt-in editor producer is documented in CATALOG_EDITOR_OBSERVATION.md; synthetic clean process observations do not certify descendants or inherited descriptors are closed. Results become stale immediately if anything changes after evaluation.

Host tests validate the pure evaluator and the existing targeted custody/retention/catalog cohort. They do not demonstrate acquisition/drain races, production writer exclusion, durable release, Android/device behavior, app builds or live-provider transitions. Those remain explicit future integration work.

The subsequent bounded native terminal producer is described in CATALOG_NATIVE_OBSERVATION.md. It inventories existing manager/retained-host owners and published receipt state without certifying native group, descriptor or complete launch coverage.
